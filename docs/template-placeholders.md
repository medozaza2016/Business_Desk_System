# Quotation template placeholders

Every company owns one or more template versions (`templates` table). The active version is snapshotted
into each quotation when it is issued, so editing a template never changes an existing record.

## Rendering rules

- Placeholders use double braces and **only** these characters in the name: `A-Z a-z 0-9 _`.
  Whitespace inside the braces is ignored: `{{ amount }}` and `{{amount}}` are identical.
- Values are HTML-escaped before insertion. Templates cannot inject data markup.
- Unknown placeholders render as an empty string — they never leak `{{…}}` into the printed sheet.
- Output must be a complete HTML document (`<!doctype html>` … `</html>`). The Worker injects nothing
  except an optional autoprint `<script>` immediately before `</body>`.

## Available placeholders

| Placeholder | Example | Notes |
|---|---|---|
| `{{quote_number}}` | `QA-2026-00001` | Prefix + year + 5-digit serial, or the number typed by the operator |
| `{{quote_date}}` | `05/11/2026` | Always `DD/MM/YYYY`, independent of the browser locale |
| `{{model}}` | `AUDI A8 L` | Free text, max 120 chars |
| `{{year}}` | `2012` | Free text, max 20 chars (kept as text on purpose) |
| `{{chassis}}` | `WAUZZZ4H0DN000001` | Free text, max 120 chars |
| `{{currency}}` | `AED` | From the company profile at issue time |
| `{{amount}}` | `16,500.25` | Amount in major units, thousands separated, 2 decimals |
| `{{amount_words}}` | `sixteen thousand five hundred and twenty five fils` | English words, generated by the Worker |
| `{{company_name}}` | `Challenger Cars` | `legal_name` falling back to `name` |
| `{{company_legal_name_en}}` | `CHALLENGER USED CARS EXHB. LLC` | Legal name in English (`legal_name`, falling back to `name`) |
| `{{company_legal_name_en_head}}` | `CHALLENGER` | First word of it, for the accent-coloured brand word |
| `{{company_legal_name_en_tail}}` | `USED CARS EXHB. LLC` | The rest of it |
| `{{company_legal_name_ar}}` | `شالنجر للسيارات المستعملة ذ.م.م.` | Legal name in Arabic (`legal_name_ar`); empty when the profile has none |
| `{{company_legal_name_ar_head}}` | `شالنجر` | First word of it |
| `{{company_legal_name_ar_tail}}` | `للسيارات المستعملة ذ.م.م.` | The rest of it |
| `{{company_address}}` | `Al Quoz, Dubai` | May be empty |
| `{{company_phone}}` | `+971 4 000 0000` | May be empty |
| `{{company_email}}` | `quotes@example.com` | May be empty |
| `{{letterhead_url}}` | `/letterhead_background.png` | Same-origin path to the letterhead artwork |
| `{{logo_url}}` | `/api/companies/8f3…/logo?v=…` | The company logo uploaded in Settings → *Company profile*; a 1×1 transparent GIF when none exists |
| `{{logo_state}}` | `has-logo` | `has-logo` or `no-logo` — put it in a `class` attribute to switch artwork with CSS |

Company values come from the snapshot stored on the quotation, not from the live company row — with two
exceptions: `letterhead_url` and `logo_url` stay live, so re-uploading a logo can never leave a broken
image on a reprint; and a legal name missing from an older snapshot is read from the live profile, so
quotations issued before the Arabic name existed still print it.

The legal names come from **Settings → Company profile**: *Legal name (English)* (`legal_name`) and
*Legal name (Arabic)* (`legal_name_ar`). A sheet that prints its header lockup in two tones — brand word
in the accent colour, the rest in body colour — takes the `_head` / `_tail` pair instead of styling the
value itself: values stay escaped, so the template owns the markup and the profile owns the words. The
split is at the first space, which is where both live sheets break (`CHALLENGER` | `USED CARS EXHB. LLC`,
`شالنجر` | `للسيارات المستعملة ذ.م.م.`):

```html
<div class="brand-ar"><span class="accent">{{company_legal_name_ar_head}}</span> {{company_legal_name_ar_tail}}</div>
<div class="brand-en"><span class="accent">{{company_legal_name_en_head}}</span> {{company_legal_name_en_tail}}</div>
```

## Company logo and watermark

One image serves both jobs. Upload it in **Settings → Company profile → Brand logo** (PNG, JPEG or WebP,
≤ 512 KB) and print it wherever the template asks for `{{logo_url}}`:

```html
<!-- header mark -->
<div class="brand-logo {{logo_state}}">
  <img class="logo-builtin" src="data:image/webp;base64,…" alt="">
  <img class="logo-upload" src="{{logo_url}}" alt="">
</div>

<!-- faint watermark, same file -->
<div class="watermark {{logo_state}}">
  <img class="wm-upload" src="{{logo_url}}" alt="">
</div>
```

```css
.brand-logo.has-logo .logo-builtin, .brand-logo.no-logo .logo-upload { display: none; }
.watermark.has-logo .wm-upload { /* a removed logo prints nothing */ }
.watermark { opacity: .22; }        /* watermark strength */
```

Why two tokens:

- `{{logo_url}}` degrades to a transparent 1×1 GIF instead of an empty `src`, so a template that prints
  it while no logo is uploaded never shows a broken-image icon.
- `{{logo_state}}` lets a template keep its own built-in artwork (the shipped default keeps the
  Challenger winged-C) and drop it the moment a company logo exists. Both values are plain text, so they
  stay inside the "values are HTML-escaped" rule.

Templates published **before** this feature do not contain the tokens: the upload still succeeds, the API
returns `template_uses_logo: false` and the desk warns you. Add the block above to the live template and
publish a new version. The Marshall Auctions template is an example of a company whose artwork lives
entirely in its own SVG; it simply never references `{{logo_url}}`.

`templates/challenger-cars-quotation.html` is the Challenger Cars A4 sheet with the slot wired in — a
worked example of converting an existing template. It keeps the built-in winged-C as the `no-logo`
fallback for the header mark and prints the upload as a 10 %-opacity watermark in the free band of its
footer (between the signature row and the contact block). It is a reference copy only: it is not imported
or seeded, so it is never bundled into the worker.

The image is same-origin and public to read, so it renders even inside the sandboxed preview iframes
(the print CSP already allows `img-src 'self' data:`); uploaded SVGs are refused by the API, so a logo can
never be a script-bearing document.

## Default template

`templates/default-quotation.html` is shipped with the Worker, seeded as **version 1** for every new
company, and used when a company has no active template. It is the bilingual A4 sheet (English + Arabic),
210 × 297 mm, positioned in millimetres so browser printing matches the configured letterhead.

## Editing a template

1. Settings → **Print template** → *Reload active* to load the current HTML into the editor.
2. Edit, then **Publish version**. A new version is stored and immediately becomes the active one.
   Older versions stay in the list and can be re-activated at any time.
3. Existing quotations keep the HTML they were issued with.

Hard limits: 200,000 characters per version; a version cannot be empty.

## Content Security Policy (why some HTML is inert)

Printed sheets are served with:

```
default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; font-src 'self' data:;
script-src <hash> | 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'
```

Consequences for template authors:

- **Inline `<style>` works**, external CSS does not (`style-src 'unsafe-inline'` only).
- `<script>` inside a company template never executes — this is intentional, it keeps company-authored
  HTML from running in an authenticated origin. The only script that can run is the Worker's autoprint
  snippet, allowed by its `sha256` hash when the sheet is opened with `?print=1`.
- Images must be same-origin (`img-src 'self'`) or `data:` URIs.
- Fonts must be same-origin or `data:`. The default template uses Arial (plus Tahoma/DejaVu fallbacks for
  Arabic) because system fonts print identically to what the operator sees on screen.
- No forms (`form-action 'none'`), no framing by other sites (`frame-ancestors 'self'`).

## Letterhead

`public/letterhead_background.png` ships as a neutral white placeholder so the sheet prints cleanly
before artwork exists. Replace that file with the real A4 letterhead (210 × 297 mm, 150–300 dpi) and
redeploy. The template paints it with `background-size: 100% 100%`, so the artwork must already include
the header, footer, and margins; the body content is positioned in millimetres to sit inside them.

To give a single company its own letterhead later, host the file and store a different value in
`company_snapshot_json.letterhead_url` when the quotation is created — the template needs no change
because it reads the placeholder.

### Brand line in the default template

Because the shipped letterhead is a blank placeholder, the default template ends with a discreet brand
line at 269 mm (company name, address, phone · email) so a printed sheet is never anonymous. When real
letterhead artwork that already carries the company identity is deployed, delete the `<div
class="brandline">…</div>` block in Settings → *Print template* and publish a new version — otherwise the
identity appears twice.

## Known limitations of the default sheet

- **Amount in words is English only.** The Arabic sentence carries the figure (`{{amount}}`) and the Arabic
  unit "درهم إماراتي", so the default sheet assumes an AED company. A company trading in another currency
  should edit that sentence in its own template version.
- The sheet is a **single page by design** (`overflow:hidden`, fixed 297 mm). Long model or chassis values
  wrap inside `.vvalue`, but extreme values can clip.
- Numbers use Western Arabic digits in both languages, matching the reference sheet.
